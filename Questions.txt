Describe Your Solution
Provide a detailed technical description of your solution and related components.
The Data Seeding package enables admins to export records from a source Salesforce org and import them into a destination org with relationship resolution and optional matching on key fields. It ships as a Lightning application (Data Seed) and Lightning Web Component (externalOrgQuery) that runs entirely on the Salesforce Platform. The component lets a user connect to a remote Salesforce org (or reuse the current org), discover objects and dependencies, preview SOQL queries, and start an asynchronous seeding job.

Seeding jobs are executed by Apex (DataSeedingBatch and DataSeedingService). The batch queries the source org (local or remote via REST), pages through results, discovers and resolves lookup relationships, performs inserts or updates in the destination org, and writes a CSV report to ContentVersion for download. Queries use WITH SECURITY_ENFORCED where applicable. The UI polls job status and exposes a link to download the generated report.

Key components:
- Lightning App: Data Seed (form factors Small and Large)
- LWC: externalOrgQuery (exposed to App, Home, and Record pages) and externalOrgQueryNode (internal helper)
- Apex classes: DataSeedingService, DataSeedingBatch, ExternalOrgQueryController, ExternalOrgQueryService, ExternalOrgDescribeService, ExternalOrgDmlService, ExternalOrgAuthService, and associated test classes
- Permission set: Data_Seeding_Access
- Reporting: CSV report stored as ContentVersion for retrieval by authorized users

If your solution stores any Salesforce OAuth tokens or other access tokens, describe how the tokens are stored.

Enabled
No persistent token storage. The component uses a session ID and instance URL for the duration of a user session to perform remote org queries. Session values are held transiently in component state and sent to Apex only to complete the requested action. Tokens are not written to Custom Settings, Custom Metadata, Files, or any external system.

If your solution stores any Salesforce data outside the Salesforce Platform, list all types of stored data, and describe where and how the data is stored.

Enabled
No Salesforce data is stored outside the Salesforce Platform. Seeding reports are saved as ContentVersion within the destination org and are accessible to users with Files permissions. Runtime state (such as ID remapping caches and logs) resides in memory during batch execution and is not persisted externally.
